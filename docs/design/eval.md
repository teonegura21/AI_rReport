# The evaluation: its data, runs, scores, and frozen judges

M2 measures rReport against what its videos say (ADR-0019). That needs three things before any measuring:
1. **a fixed set of videos**, each with the right to use it;
2. **their captions, frozen**, so that a change on YouTube changes nothing in the eval;
3. **what each video says**, written down once by a person: its gold annotation.

P16 builds that data, and the tools that make it cheap to produce. Writing down everything a lecture says takes a person most of a day; correcting a good draft takes an hour or two. So models draft it, as **silver**, and a person corrects it into **gold** with a review sheet beside it (runbook R2). P23 takes the set's videos through the article stages and scores each article by code ([Runs and scores](#runs-and-scores)); P24's frozen judges read what code cannot ([The judges](#the-judges)). P25 compares two runs and gates a candidate against its baseline ([Comparisons and the gate](#comparisons-and-the-gate)); P26 sweeps variants of the pipeline against one baseline, and draws every run on one page ([Sweeps and the report](#sweeps-and-the-report)); P27 checks the judges against a person's labels ([Labels and calibration](#labels-and-calibration)).

## The set

```toml
[[video]]
id = "fed-talk-1"                # [a-z0-9-], 1 to 64, not starting with '-': it names a directory
title = "Monetary policy, explained"
url = "https://www.youtube.com/watch?v=abc123XYZ_0"
type = "talk"                    # talk | conversation | tutorial | narrative
captions = "manual"              # manual | automatic
split = "dev"                    # dev | test (ADR-0019)
licence = "us-public-domain"     # cc-by | us-public-domain
attribution = "Board of Governors of the Federal Reserve System"
snapshot = "1acc46b4…"           # optional: the snapshot's hash, pinned
```

**Read strictly.** A set is written by hand, and a slip that was silently ignored would measure something else than its author meant: a video without its split, captions of the wrong kind averaged in. So every key is asked for by name and type (`detail::Table`). A missing key, an empty text, a value out of its choices, a key nobody asked for, two videos with one id, or broken TOML is an error that names the file, the video's number and the key: `eval/sets/m2.toml, video 2: unknown key 'lisence'`.

**Only CC BY or the US public domain.** The eval commits its snapshots and may publish what it makes of them, so it needs the right. Non-commercial and no-derivatives licences are refused by the reader itself: `licence` has two choices.

## Snapshots

`rreport eval fetch` reads each video **once**, through the pipeline's own source stage (yt-dlp, the captions in the language spoken: [pipeline.md](pipeline.md#the-source-stage)), and keeps what it read in `eval/data/<id>/`:
- `<id>.source.json`: the source artifact itself, written readably (indented);
- `snapshot.toml`: its hash, when it was read (to the second, UTC), and from where.

From then on the eval reads the snapshot, never YouTube.

- **The snapshot is the artifact.** Its hash is the BLAKE3 of the artifact's canonical JSON, which is also its hash in a library. `rreport ingest eval/data/<id>/<id>.source.json` reads it as a saved source (`*.source.json`: [pipeline.md](pipeline.md#the-source-stage)), so a snapshot runs through the same stages, with the same keys, as the video would. A test runs the source stage on a snapshot and gets the snapshot's hash back.
- **Pinned by hash.** `snapshot.toml` keeps the hash, so a snapshot edited by hand, or damaged, is refused (`Errc::integrity`: "fetch it again"). The set may pin the hash too; a snapshot fetched again that differs from the pin is refused (`Errc::conflict`) until the set says otherwise. `eval fetch` prints the line to pin.
- **Checked before it is kept.** The captions must be of the kind the set says: a set that expects manual captions and gets automatic ones is a mistake to stop at, not a result to average in. A video the set calls CC BY must carry YouTube's Creative Commons line: only a licence the page states can be relied on. US federal works carry no such line, and need none.
- **Read once, unless asked.** A snapshot kept is never read again; `eval fetch --again` reads it again, on purpose, and the pin decides whether the new one may replace it.

## Gold

```toml
video = "radium-talk"
snapshot = "1acc46b4…"          # the snapshot it was annotated on
status = "gold"                 # silver: drafted, unreviewed; gold: reviewed
reviewer = "Ada"                # required for gold
drafted_by = "annotate@1 ×3 on qwen3.8-27b-q8; annotate_more@1 on gemma-4-26b-a4b"

[[fact]]
id = "F2"                       # kept when facts are corrected
start = "0:06"                  # as a player shows it: "3:04", "3:04.25", "1:02:03.5"
end = "0:10"
importance = "core"             # core: an article without it misses the point; detail
found = 3                       # how many of the drafts found it
quote = "Marie Curie measured 7 samples in 1902."
claim = "Marie Curie measured seven samples in 1902."

[[must_quote]]
start = "0:09"
end = "0:15"
quote = "the proof load"

[[term]]
term = "proof load"
meaning = "the most a bridge carries without bending for good"
```

**Anchored to the timeline (ADR-0009).** A transcript's sentence numbers change whenever its segmentation improves, so gold never names an `S#`. A fact holds the stretch of the video that says it and a quote of the words that say it, and is found again in any transcript by both: the quote, said verbatim (`rr/text/align.hpp`: case, accents and punctuation aside) in the sentences said within the stretch, give or take two seconds (`said_there()`, `kAnchorSlack`). The slack is there because captions' times are approximate, and a person reads them off a player.

**Times as a player shows them.** ADR-0019 writes the anchor as `(t0_ms, t1_ms, quote)`. The file spells it `start` and `end`, as players show times, because people read and correct it against a player: "3:04.25" is checked at a glance, 184250 is not. The reader also takes plain seconds ("184") and hours ("1:02:03"); the writer drops trailing zeros. The file reads back equal to what was written, quotes, backslashes, new lines and control characters included.

**Silver until reviewed.** Models write `status = "silver"`; a person who corrected the file sets `status = "gold"` and names themself as `reviewer`. The eval scores only gold. A gold file without a reviewer is a problem the sheet reports.

**What is wrong is said as what to correct** (`gold_problems()`): a fact or must-quote that ends before it starts; a quote not said in its stretch ("F7: "We call it the proof…" is not said between 0:09 and 0:15: correct its quote, or its times"); gold without a reviewer. A long quote is shown cut at 60 bytes, never inside a character.

## Silver, drafted by models

The `annotate` stage runs after `source` and `transcript`, as a pipeline stage like any other: keyed, cached, accounted and resumable. An annotation interrupted halfway asks again none of the calls it made (ADR-0020).

1. **Windows.** The transcript is cut into windows of whole sentences, each sent with a few sentences of context on either side: up to three, as many of them as fit 1,000 bytes of lines. The context lets a model read the window's first and last sentences as they were said; only the window's own sentences may be cited.
2. **The commander drafts each window three times, thinking** (`prompts/annotate`). The three drafts are three samples of one reading of the prompt (`n = 3`, plan P3), with seeds the job's salt derives: a replicate draws new samples. Every item cites the sentences that say it and quotes them; a term must be said in the window. A draft that breaks these rules is sent back with its problems, at most eight at a time, said as what to do instead ("fact 3: "Pierre Curie measured 7 samples" is not what S5 says, word for word: copy the quote from it"), and climbs the escalation ladder (rr/agents/ladder.hpp).
3. **The drafts are joined.** Two facts are one when they cite a sentence in common and one's quote holds the other's. The fact is kept once, with the first draft's words, on every sentence any draft cited, and `found` counts the drafts that found it (a draft listing a fact twice counts once). A fact most drafts call detail is detail; otherwise core, ties included: an account that keeps too much is corrected faster than one that misses the point. Must-quotes are joined the same way; terms by their folded form, a meaning filling an empty one and never replacing one.
4. **A model of the other family reads each stretch again** (`prompts/annotate_more`), on the infantry, with the facts found in that stretch beside the sentences ("- [S12, S13] claim"), and adds what they miss with `found = 0`. Two families see differently (ADR-0017). Its additions are joined in by the same rule, so a fact it repeats in other words is dropped only when its quote is the same.
5. **Silver** is the artifact (`schemas/artifacts/silver.json`): facts with their sentences, times, quotes, claims, importance and `found`; must-quotes; terms; who drafted it (`annotate@1 ×3 on <commander>; annotate_more@1 on <infantry>`). Once the job is done, `run_annotation()` writes it as the video's gold file, status silver, facts numbered F1, F2, … in the order said, times and quotes only.

**Windows fit their engines exactly.** A window is filled with whole sentences up to a size its engine suggests (`window_sizes()`):
- the commander's up to 12,000 bytes of lines: after its thinking budget, a third of the room for the window and two thirds for an answer of up to twice what it reads (a dense passage gives a fact a sentence, each with a quote and a claim of its own, in JSON);
- the other family's up to 3,000 bytes: after its answer (1,024 tokens), half the room for the window and half for the facts found in it.

Then its mission is built and, while the engine would not hold it (`agents::Army::holds()`: the very test the squad applies), it gives up sentences from its end, to the next window: the pipeline's windows, shared since with every stage that reads a transcript ([pipeline.md](pipeline.md#what-every-stage-that-asks-models-shares)), which find the largest window the engine holds by bisection. So no mission is ever refused for its size, whatever the title, the context or the facts found, and a sentence too long for its engine even alone is a finding ("the sentence S3 (0:06 to 0:40) has no draft: even alone, with its context and an answer, it is more than qwen-commander holds at once"). On a 48 GB pod (the commander 32,768 tokens a sequence, the infantry 4,096 a slot) the windows are 12,000 and about 2,800 bytes. A test with a commander holding 3,800 tokens shows windows giving up sentences, every sentence drafted exactly once, and each answer's budget twice what it reads.

**The stage's key** holds the prompts' versions and content hashes, the army's fingerprint (its models and how they sample, the thinking budget included), the window sizes **and what each engine holds**: how the transcript is cut depends on the engines' sizes, which `army_fingerprint()` leaves out (they change how fast, not what, for every other stage). The stage samples, so the job's salt is in its key too.

**Findings.** A window no draft passed the checks for, the models declined, or a job ceiling stopped is a finding naming its sentences and minutes, pass by pass, in the order said. A ceiling makes the result this job's alone (`reusable = false`): a job allowed more would have drafted more.

### Jobs that annotate

An annotation is a job of the library, of its own kind (`library::JobKind::annotation`, `migrations/0005_job_kind.sql`). Its source is the snapshot, never YouTube.

- `rreport eval annotate` takes up an unfinished annotation job of the same snapshot (running, stopped, needing the user) rather than starting another: its memo answers every call it made. A failed job is not taken up: what failed would fail again.
- `rreport resume` refuses an annotation job: it runs the article's stages, and would mark the job done without its annotation. `rreport jobs` shows each job's kind.
- A gold file is never replaced by a draft once reviewed, and a silver one only with `--replace`. A gold file that cannot be read is never replaced either: it may be a person's work half done.

## The review sheet

`rreport eval sheet ID` prints Markdown that a person keeps open beside the gold file:
- each fact: its stretch as a link to that moment of the video (`&t=184s`), how many drafts found it, its importance, claim and quote, and whether the quote is said there (✓ or ✗);
- a fact only one draft found is marked `?`, the first to doubt;
- must-quotes and terms;
- what to correct: `gold_problems()`, and, first, gold drafted on another snapshot than the one kept now (YouTube's captions changed, and every anchor must be checked again).

**Checked without a model.** Quotes are aligned without their punctuation, so the sheet checks them against the snapshot's captions cut into sentences as they are (`caption_transcript()`): reviewing never needs the pod.

## Runs and scores

A number about articles means something only next to how they were made. A **run** fixes that: one set, one split, one tier, a number of replicates, under a label that compare and gate (P25) name it by (`rr/eval/run.hpp`, `migrations/0006_eval.sql`).

**`rreport eval run --label L`** takes each video of the split through the article stages, once a replicate:
- its jobs are ordinary article jobs, made from the video's snapshot: they share the stage cache, the call log and the battle log; `rreport jobs` lists them, and `rreport report` pages them;
- a replicate's number is its job's salt, so the replicates draw different samples (ADR-0020's seeds derive from it), while a run made again draws the same;
- replicate by replicate: a run interrupted early has every video once before any twice;
- a job is made when its turn comes, never ahead, so an interrupted run leaves no job that never started;
- the same label again takes the run up: a job done is kept, one not done is resumed (its memo answers every call it made), one missing is made. A label names one run: asked of another set, split, tier or number of replicates, it is refused.

**`rreport eval score --label L`** scores each job done by code alone (`rr/eval/score.hpp`). The scores are kept in the library, and replaced when the job is scored again:

| Metric | What |
|---|---|
| `sentences_accounted`, `atoms_told`, `invalid_markers`, `quotes_kept`, `numbers_kept` | The Fidelity Report's figures, by the code that computes the page's (`report::checked()`), so the two never disagree |
| `gold_quotes_kept` | Gold's must-quotes said verbatim in the article as a reader reads it: its prose, without markers |
| `gold_terms_used` | Gold's terms the article uses |
| `facts_cited`, `core_facts_cited` | Gold's facts, all and core, some atom of whose sentences the article cites: the facts it may tell. Whether it tells them is a judge's to say (key-fact recall, P24); a fact not cited is not told, so these bound it from above |
| `length_ratio` | The article's words over the transcript's |
| `minutes`, `minutes_per_video_hour` | The job's running time, across its resumes: on a pod of its own, its GPU's |
| `calls`, `prompt_tokens`, `completion_tokens`, `escalations` | Model calls answered; every attempt's tokens; missions answered past the rung they were ordered at |

- **Gold is scored against only when reviewed, and for the snapshot read.** Silver is never scored, and gold written for another snapshot than the one the job read has anchors that may not hold. Either way the job is scored without it, and it is said.
- **A share with nothing to share is no score**: an article with no number to keep has no `numbers_kept`, rather than a 100% that would flatter an average.
- **A fact's sentences** are found as the review sheet finds a quote (`said_there()`): of the sentences said within its stretch, give or take two seconds, those its quote, aligned verbatim, covers (`sentences_saying()`).
- **The scorer is named and versioned** (`code@1`): a change to any metric's definition bumps it, so scores of different definitions are never mixed.

**`rreport eval export --label L`** writes a row per video and replicate: the run's label and tier, the video's type and caption kind, its job, its scorer, then each metric, a metric the entry has not an empty cell (`rr/eval/export.hpp`). CSV for a spreadsheet; JSON for the statistics (P25).

## The judges

Code bounds what an article tells (`facts_cited`) and checks what it keeps word for word; it cannot read. Whether a reader of the article learns a fact, and whether a sentence says only what the video says, the eval's **judges** read (P24, `rr/eval/panel.hpp`, `rr/eval/judgement.hpp`).

**Not the pipeline's judges.** The pipeline asks its own `judge` and `flow` prompts to choose between drafts, so the writer's output is, in effect, optimised against them. An eval that read with the same prompts would measure how well the pipeline pleases itself: once a measure becomes a target, it stops measuring (Goodhart). So the eval asks its own prompts (`eval_fact`, `eval_support`, `eval_flow`, [prompts.md](prompts.md#the-evals-judges)), and reads each sentence against **the video's own words**, the transcript's sentences behind the atoms it cites, never the atoms: an atom that misread the video vouches for nothing.

**A frozen panel.** A number a model gives means something only next to the model that gave it, the words it was asked in, and how. So the judges are a panel frozen in a file, `eval/judges/eval-v1.toml`:
- its prompts by version and hash, as the manifest has them;
- its judges by role and by the SHA-256 of the model file each must serve: a judge is those weights, not a name. eval-v1 pins the 48 GB profile's pair (`qwen3.8-27b-q4`, `gemma-4-26b-a4b`); a pod that serves other files (the 80 GB profile's 8-bit commander, a lighter infantry under trial) serves the 48 GB profile to judge, and `eval judge` says which file it misses;
- the judging procedure's version (`kJudgingProcedure`): which sentences a judge is shown, and how its answers are read.

A change to any of them makes a new panel, `eval-v2`, never an edit of `eval-v1`, and the panel's own test fails until one is made. Every score a panel gives is kept as `judges@<panel>`, beside the code's (`code@1`), and scores of different panels are never compared. Until a person's labels have shown that the panel reads as they do (P27), the file says `calibrated = false`: its scores are reported, and the gate (P25) ignores them.

**Two families, every item.** Each item is read by every judge of the panel, the commander's family and the infantry's, since one model favours its own kind (Verga et al., 2024, PoLL); an item's value is the mean of its judges' readings, and how often they agree is a score of its own. An item two judges read differently is the first a person settles in P27.

**What each judge is shown.**
- *A fact* (`eval_fact`), with the article's sentences most likely to tell it: those citing an atom of the sentences that say it (as `facts_cited` finds them), then the best three by BM25 on its claim and its words, in the article's order, twelve at most. A sentence in other words than the fact's is still found by its citation, and one that tells it without citing its atoms by BM25. A fact with no such sentence is not told, and no judge is asked. Verdicts: told, partly (a number, who or a condition missing or blurred), not told.
- *A paragraph* (`eval_support`), sentence by sentence, each with the video's sentences it rests on (`S12 [1:02, Ada] The words.`, the speaker inside the brackets so that a quote of the words is never a quote of the label); a sentence citing nothing is shown its paragraph's. Issues: none, adds, softens, intensifies, misattributes, contradicts.

**Evidence first, and checked.** Every answer quotes its evidence before its verdict (the schema's field order), and every passage it quotes between double quotes must be in what the judge was shown, word for word, case and punctuation aside; a fact told needs one. An answer quoting what it was not shown is sent back once, then the item is unread for that judge: a verdict resting on words the judge made up is no reading. Judges answer greedily, without thinking, and never climb the escalation ladder: a frozen judge is those weights asked that way, not whichever model answers last. A mission its judge's engine cannot hold is cut (a paragraph, in halves) or, a sentence or a fact alone, left unread: never sent, since the army refuses a squad with one mission it cannot run.

**As a job.** A judgement is a library job of its own kind (`judgement`, migration 0007) with one stage, reading the article job's artifacts and the reviewed gold's facts. Its key holds what the judges read (the transcript's, the atoms' and the article's hashes, the facts, the title the prompts show) and how they are asked (the panel, each judge's file, how much its engine holds, how it samples). So an article judged again, unchanged, asks nothing, even through another job's article; an interrupted judgement is taken up by its memo; and the judges' calls are the judgement's, never the article's costs. `eval_judgements` keeps which job judges which article under which panel.

| Score (`judges@<panel>`) | What |
|---|---|
| `facts_told`, `facts_told_partly`, `core_facts_told` | Of the reviewed gold's facts (all, all, core), the share a reader learns from the article: told; told at least in part |
| `sentences_supported` | Of the article's sentences, the share the video supports, saying only what it says |
| `adds`, `softens`, `intensifies`, `misattributes`, `contradicts` | The share of sentences read so |
| `facts_agreement`, `sentences_agreement` | Of the items two judges or more read, the share they read alike |

An unread reading is left out of its item, and an item no judge read out of its score. Without reviewed gold, an article is judged sentence by sentence only, and it is said.

**`rreport eval judge --label L [--panel P]`** judges each done job of the run: the panel checked against this rreport first (a prompt changed since it was frozen is refused), then a judgement job each, its scores kept. The same command again judges only what changed.

## Comparisons and the gate

A number about one run says how good its articles are; a decision is about two: keep a change, or not. `rreport eval compare` lays two runs side by side, every metric; `rreport eval gate` decides, by a file a person reviews, whether a candidate may replace its baseline (P25, ADR-0019; `rr/eval/stats.hpp`, `rr/eval/compare.hpp`, `rr/eval/gate.hpp`).

**The video is the unit.** A run is a sample twice over, of videos and of the models' draws, and a difference of two means may be the change or chance. So a comparison works video by video: each video's replicates are averaged first (three replicates of one video are one video, not three), then each video's difference, candidate − baseline, on the videos both runs scored. Its 95% interval comes from 10,000 resamples of those differences with replacement (the paired bootstrap; Koehn, 2004), drawn by `mt19937_64` seeded from the metric's name, each video picked by the generator's own number modulo their count: the standard fixes the generator's numbers but not its distributions' algorithms, and a comparison must print the same interval on every machine. A test pins one interval, computed independently by a Python `mt19937_64` that reproduces the standard's own check value. Beside it: the standard error of the mean difference, and 2.8 of them, the smallest difference these videos detect four times in five, so that "no difference" says how small "none" is.

**Common random numbers.** Replicate *r* of both runs draws under salt *r* (ADR-0020), and a stage a change leaves alone is the same stage run, through the stage cache: a candidate that changes only the writer asks the engines nothing until the writer, and its difference is the change's alone. The end-to-end test shows it: a second run of the same pipeline asks nothing at all.

**`compare`** prints, metric by metric, grouped by the scorer that computed them (the code's first, so a reader sees at once which numbers rest on judges not yet calibrated): the videos both runs scored, A, B, B − A, its interval, its standard error, 2.8 of them, the gate's margin where the gate holds the metric, and what the interval shows: *better* or *worse* when it lies wholly on one side of zero, *no difference* when it holds zero, *higher* or *lower* for a metric better neither way. Two runs scored by different versions of a scorer measure different things: that metric is not compared, and the message says which run to score again. Videos one run scored and the other did not are left out, and listed. `--metric M` shows one metric video by video.

**The gate** (`eval/gates/<name>.toml`, `default` shipped):
- *Invariants*, on every entry of the candidate, every video and replicate: at least the bound for a metric better higher, at most for one better lower. An entry never scored makes the invariant inconclusive; an entry scored without the metric (an article with no number to keep) keeps it, with nothing to break.
- *Gated metrics*, each with a margin δ, in the metric's own units: a non-inferiority test. A metric passes when the worse end of its interval is −δ or better, so that a real regression larger than δ passes at most 2.5% of the time, whatever the noise. It fails as *worse* when the whole interval lies on the worse side of zero, past its margin, and as *inconclusive* when it spans both −δ and zero.
- *Inconclusive fails the gate*, whatever the cause: an entry not scored, a metric neither run has, scorers that differ, fewer than two videos. The remedy is more data (more videos, more replicates, a run finished), never a wider margin at gate time.
- A metric the frozen judges score counts once a person has calibrated their panel; until then it is shown, with its interval, and ignored. Costs, and metrics better neither way, are never gated: the file refuses them.

**The margins, against an A/A run.** Margins under the noise would make the gate a coin toss. The noise is measured as ADR-0019 has it: the baseline run again with nothing shared, its replicates under other salts (`rreport eval run --label base-aa --first-replicate 3`; migration 0008 numbers a run's replicates from its first). `rreport eval gate base base-aa --aa` then checks the gate itself, rather than a change:
- the two runs must be one pipeline's: the same set, split and tier, and replicates that share no salt (overlapping salts share stage runs and would hide the noise: refused, saying which `--first-replicate` to use);
- each gated metric's A/A standard error, how often an unchanged pipeline passes it alone (Φ(δ/SE − 1.96): 80% at δ = 2.8 SE), and the margin that would give 80%;
- how often an unchanged pipeline passes every counted gated metric at once, which must be 80% or more: each metric's A/A differences centred on zero (an unchanged pipeline differs by chance alone), the videos resampled 10,000 times with one draw for all metrics, so that metrics that move together are counted together, and each draw judged by the gate's rule on the interval's normal approximation;
- the metrics whose A/A interval leaves out zero. With ten metrics chance does that to one now and then, so it is no failure by itself; one that keeps doing it points at a draw the salt does not reach.

**The metrics, in one table** (`rr/eval/metrics.hpp`): every metric with the scorer family computing it, which way it is better, and whether it is a cost, in the order `compare` lists them. Better higher: what an article accounts for, keeps, cites, tells, the sentences the video supports, and the candidate's flow preferred; better lower: invalid markers, each judged issue, and every cost; better neither way: the length ratio and the judges' agreement. A test of each scorer checks that it computes exactly its family's metrics of the table, so that a comparison lists, and a gate holds, exactly what is scored. One metric is no run's own: flow is read pairwise, between two runs' articles, when they are compared (below).

### How an article reads, pairwise

Whether an article reads well cannot be scored alone: "reads well" means "reads better than that one". So `rreport eval compare A B --flow` reads each video's two articles side by side (P25b, `rr/eval/flow.hpp`), with the panel's own prompt, `eval_flow`, never the pipeline's `flow`, which the writer's drafts are chosen by:
- *Pairs.* Replicate *k* of A with replicate *k* of B, in their order: under the same salts when the two runs start at the same replicate, so that the two articles differ by the change and not by the dice. Runs of unequal replicates pair the first of each, and say so.
- *Parts.* The two articles retell one transcript, but may cut it differently: two tiers outline one video in other sections. So each article is cut at its headings, each section is found on the video by the sentences of the atoms it cites, and the two articles' sections are joined wherever they overlap there: each part covers the same stretch of the video in both, the same things told, to be judged only on how they read. Two articles of one outline make a part a section. A section citing nothing is read with the one before it (a title, with the one after); a stretch only one article tells is no part: what an article tells is coverage, which the other metrics measure.
- *Both orders, every judge.* Each part is shown to each judge twice, A's version first, then B's, in `<first>` and `<second>`: each version its sections whole, headings and prose, markers stripped, in the article's order; the stretch named by its times ("the stretch of the video from 1:30 to 3:55"), never by either article's heading. A side wins a part only when both orders prefer it (`reason::swapped()`): a judge that prefers whatever comes first gives a tie, and its disagreements are counted, the panel's position bias, which calibration will report (P27). A part an engine cannot hold is unread, a finding: it is the smallest stretch both articles tell alike, and is not cut.
- *The score.* A part is worth +1 when B wins, −1 when A wins, 0 for a tie, averaged over the judges that read it (PoLL); a pair is worth the mean over its parts read, and a video the mean over its pairs. These are B's preference, from −1 (A always) to +1 (B always): differences already, so `compare` resamples them over the videos as it does any other difference (`compare_pairwise()`), and shows them as the row `flow`, among the panel's, with no A and no B. `--metric flow` shows each video's.
- *As jobs.* A pairing is a library job of its own kind (`pairing`, migration 0009, which makes `jobs` anew as 0007 did), its one stage keyed by both articles, their atoms, the transcript, the title, the panel and its judges' engines: a pair compared again, unchanged, asks nothing, even through other jobs; an interrupted one is taken up by its memo; and its calls are never either article's costs. `eval_pairings` keeps which job compares which two article jobs, in which order, under which panel.

## Sweeps and the report

Choosing a default (runbook R6) asks one question many times: is this variant better than the baseline, by how much, and at what cost? A **sweep** writes the questions down once, each with why it is asked; the **report** shows every answer on one page (P26; `rr/eval/sweep.hpp`, `rr/eval/history.hpp`).

**Variants, named by what they change** (`reason::find_tier()`). `max+write.thinking=true` is `max` with its writer thinking; `thorough+write.drafts=3+plan.mode=group` changes two stages of `thorough`. A change is `stage.key=value`, its value true or false, a whole number, a number, or else a word, and the variant is read by the tier files' own strict reader: an unknown section or key, a value of the wrong type or out of range, a key changed twice, each is refused, naming the variant whole. A variant is accepted wherever a tier is (`ingest --tier`, `eval run --tier`), and `resume` takes up a job of one by its name alone: nothing is stored, since the name is the definition. A stage's cache key holds the stage's settings, never the tier's name ([reasoning.md](reasoning.md#tiers)), so a variant runs again only the stages it changes and those after them that read what they made, and two names of the same settings share everything.

**A sweep** (`eval/sweeps/<name>.toml`, read strictly): a baseline tier, and variants, each with a label, a tier, and why it is tried, for whoever reads the sweep later. `eval/sweeps/r6.toml` is runbook R6's: what each step of `max` buys (thinking while drafting, four drafts, the recall pass, three atomize samples, the commander's rulings, the seams' second check), one draft more fused from the four (Self-MoA, P29), two ways to spend fewer atomize samples (a third only where two disagree; a second only where the first was unsure, P28), and the tiers below it.
- `rreport eval sweep NAME` takes the baseline, then each variant, through `eval run`, `eval score` and `eval judge` (not with `--no-judge`), as the runs `<name>-baseline` and `<name>-<label>`. A run that exists is taken up, as `eval run` takes it up, so an interrupted sweep is taken up by the same command. Then it prints, for each variant, the metrics whose interval leaves out zero, which way and by how much; how many show no difference, and how many could not be compared; and the `eval compare` that shows every row.
- *Under the same salts.* Every run of a sweep numbers its replicates from 0: its variants differ by their change and not by the dice, and every stage a variant leaves alone is the baseline's own run, through the stage cache (ADR-0019, ADR-0020). A variant that spends as the baseline does, whatever it is called, is refused: it would compare the baseline with itself.
- *On the dev split, two replicates by default* (ADR-0019): a sweep explores. The test split is kept for gates, and a sweep file cannot name it.

**The report** (`rreport eval report [--out FILE] [--metric M]`, `<eval-dir>/report.html` by default): one page, the library's eval runs as they are when it is written.
1. *Quality against cost*, an SVG chart: each run a point at its means over its videos, each video's replicates averaged first, with bars spanning each mean's 95% interval from resampling the videos, as a comparison resamples them. Up is `--metric` (default `facts_told`, the facts a reader learns, once any run is judged; else `atoms_told`); across, minutes per video-hour: wall-clock minutes, which are GPU-minutes only on a pod running the eval alone (ADR-0019). A run missing either is listed under the chart, not plotted.
2. *The runs*, newest first: what each is (set, split, tier, replicates), how far it got (entries, scored by code, judged), and the means of five headline metrics.
3. *Each run's videos*, folded: a row a video, a column a metric, each the mean over the video's replicates.

The axes stand on round steps (1, 2 or 5 times a power of ten); a value that a division's rounding puts a hair off a tick (0.6 / 0.1 is 5.999…) is on it, and gets no step of room it does not need. Every text on the page is escaped.

## Labels and calibration

The judges' numbers count only once a person's labels show the judges read as the person does (ADR-0019): until then the gate ignores every judged metric, `facts_told`, M2's own, among them. P27 asks the person the panel's own three questions, on items the panel read, and measures the agreement (`rr/eval/labels.hpp`, `rr/eval/calibration.hpp`, `rr/eval/calibrate.hpp`; runbook R5).

**What is labelled.** A label is a judge's question asked of a person, on the same evidence:
- a *fact*: is this gold fact told by these sentences of the article? (`told`, `partly`, `not_told`, as `eval_fact` answers), shown its claim, its quote, when the video says it, and the article's sentences the judges were shown, numbered as they saw them;
- a *sentence*: does the video support it? (`none`, `adds`, `softens`, `intensifies`, `misattributes`, `contradicts`, as `eval_support` answers), shown the video's lines the judges were shown;
- a *part*: which of two versions of a stretch of the video reads better? (`first`, `second`, `tie`, as `eval_flow` answers), shown both versions, headings and prose.

The file shows what the judges were shown, never what they answered: labels are made blind. A part's two versions come in a drawn order, recorded in the file, so that the person's own taste for whatever comes first averages out; the coin is seeded by the file's name, the video, the replicate and the part's place, so that the same labels draw the same orders on every machine.

**`rreport eval label NAME --label RUN [--against B] [--panel P]`** draws the items: from every item of the run the panel read (a fact or a sentence one judge read at least; a part one judge read in both orders), uniformly, without replacement, by `mt19937_64` seeded with the FNV-1a of the file's name and the kind, as the bootstrap draws. 15 facts, 15 sentences and 10 parts by default: forty items, about an hour (ADR-0019 asks for 30 to 50). Parts come from the pairings of `RUN` against `B`, which `eval compare --flow` made. The facts' words are each video's reviewed gold's, as the judges read them. It never writes over a file that holds a verdict: that is a person's work.

**`rreport eval calibrate NAME`** compares, judge by judge and kind by kind, each judge's reading of every item labelled with the person's verdict (a part's verdict turned into the side it prefers, A the run, B the run read against it; a judge's reading of a part is its two orders' side, a disagreement a tie, as flow counts it):
- *Cohen's κ*, agreement beyond chance: (p_o − p_e)/(1 − p_e), p_e the agreement of two readers who say each class as often as these two do. Raw agreement flatters a judge on a skewed set: one that calls every sentence supported agrees 95% of the time with a person who finds one in twenty unsupported, and has κ 0. A κ of one class only is undefined, and says nothing of the judge.
- *Each class's precision and recall*, each with its Wilson 95% interval: on the few items a class gets in an hour, the normal approximation's interval is too narrow, and crosses 0 and 1. A judge that says a class at its own rate q, whatever the truth, has a precision of the class's share p among the person's verdicts, and a recall of q; a class clears its bars when precision's lower bound is above p and recall's above q. A class only one of the two used cannot clear them.
- *A judge passes a kind* when κ is at least 0.4 (a slack of 1e-9 keeps a κ of exactly 0.4, which floating point computes as 0.39999999999999997, at the bar) and every class either used clears its bars. *The panel passes* when every judge passes every kind: its one `calibrated` flag counts every judged metric in the gate, or none, so a kind without labels cannot pass.
- *Biases*, over every part of the two runs' pairings, reported with their intervals and no bar: each judge's flip rate, how often its two orders disagreed (position bias), and among its consistent preferences between versions a fifth apart or more in words, how often it preferred the longer (length bias).

The command never edits the panel's file: when the panel passes, it says which line to change, and a person commits it, reviewed like code.

## Decisions

- **The snapshot is the source artifact, not a format of its own.** One artifact, one hash, one reader: the eval, `rreport ingest` and the library agree on what a snapshot is without a converter.
- **The eval's own strict TOML reader** (`toml_io.hpp`), rather than sharing `rr_reason`'s tier reader: the tiers fill defaults, while these files require their values, and a shared reader waits for a third format.
- **A job's kind in the library**, rather than a database of the eval's own: annotation jobs share the stage cache (a snapshot's transcript is the video's), the call log and the battle log, and `rreport jobs` shows them beside the articles.
- **`Army::holds()`, not a copy of the army's sizing.** The stage asks the army whether a mission fits, with the estimator and presets the squad will use, instead of predicting it: a prediction would drift from the army's rules, and a mission the squad refuses fails every mission of the squad with it.
- **The oracle answers annotation by a rule a test can predict** (`rr/oracle/answers.hpp`): every sentence of five words or more is a fact, quoted whole, core when it holds a digit; the other family adds every sentence of three or four words its notes do not cite. Silver has no single right answer; a predictable one lets the tests check every step of joining.
- **A judgement is a job, not a table of the eval's own** (P24). As a job it has the stage cache (an unchanged article is never read twice), the memo (an interrupted judgement asks again only what it had not), and the call log and battle log, where the judges' calls stay apart from the article's costs. A table of readings would have had to rebuild all three.
- **Scores by scorer family.** A scoring replaces what its own family kept for an entry (`code@2` replaces `code@1` whole), and leaves the other families' (`judges@…`): the code's numbers and the judges' are kept side by side, each saying who computed it.
- **Migrations may rebuild a table.** Adding the judgement kind needed `jobs` made anew, which SQLite allows only with foreign keys off; rr_db now runs every migration so, checking every reference before it commits ([database.md](database.md#migrations)).
- **Flow, pairwise, by the video's stretches** (P25b). Which of two articles reads better needs two runs to pair, so its prompt, `eval_flow`, was pinned in eval-v1 with the others (P24), and asking it changes no panel. Its parts are stretches of the video both articles tell, found by what each cites, not sections matched by heading: two tiers may cut one video differently, and a heading names a section in one article only. A part judged so differs in how it reads, not in what it tells, which coverage measures apart.
- **A gate cannot hold flow yet.** No run scores it: it exists only between two runs' articles, read when they are compared. A gate holding it would read pairs at gate time; it waits for calibration (P27) as every judged metric does, and the gate file refuses it meanwhile, saying why.
- **Noise from an A/A run, not from a run's own replicates** (P25). A first draft took the noise from pairs of the baseline's own replicates, which needs no extra run. But that is noise of one replicate against one, not of the three-replicate means a comparison weighs; and ADR-0019 already says how noise is measured and margins set: an A/A run under disjoint salts, the whole gate at once. One notion of noise is kept, the ADR's.
- **An inconclusive gate fails.** A gate that let a candidate through because a run was unfinished, or scored by another scorer, would pass changes nobody measured. The exit code is 1 for *worse* and *inconclusive* alike; the text says which, and what would decide.
- **Variants named by what they change** (P26), not files of their own. A file would need a place, a review, and a way back to it from a job; a name carries its whole definition into the run's spec and the job's tier, and `resume` needs nothing else. It is read by the tier files' own reader, so a variant is refused exactly where a tier file would be; and a test checks that every shipped tier writes out every section, so that a change always has a section to set.
- **A sweep's runs are ordinary runs.** A sweep is `eval run`s with fixed labels, salts and split, not a mechanism of its own: each of its runs is compared, gated, exported and drawn as any other, and the sweep is taken up as they are.
- **One page, nothing fetched.** The report draws its chart in SVG with its own code: no script, no library, no font from elsewhere, so that it opens anywhere, offline, as an article's page does ([report.md](report.md)). It is written when asked, never kept in the library: every number on it is computed again from the scores.
- **Labels drawn uniformly, never enriched** (P27). Drawing the items the judges disagree on would find their weak spots faster, and bias every number calibration gives: κ and the precisions would describe the hard items, not the run. A rare class may go undrawn: more labels, under another name, find it.
- **Every kind, or the panel does not pass.** The panel's one `calibrated` flag (P24) counts every judged metric in the gate or none; a flag per kind would let facts count before flow is checked, and the gate's rule would grow with it. Calibration asks for labels of all three kinds instead.
- **The file shows the judges' evidence, numbered as they saw it.** A person who read the whole article would judge the candidate sentences' choice as well as the judge; that choice is tested by code (`fact_candidates()`), and the labels measure the judges.
- **Margins in a file, never at gate time.** `eval gate --aa` says which margin each metric needs; a person writes it in the gate file, reviewed like code. Nothing widens a margin to let one candidate pass.

## What waits

- **Flow in the gate.** Once the panel is calibrated (P27), `eval gate` could read pairs as `compare --flow` does; until then the gate file refuses `flow`.
- **Models in a sweep.** A variant changes a tier, not the pod's models. Runbook R6's bake-off of infantry models runs the sweep once per pod profile, each copy of the file under its own name: under the same name, a second profile would take up the runs the first one made.
- **The margins themselves.** `eval/gates/default.toml` ships with margins of a point or two of a share; the A/A run of runbook R4 says whether the real pipeline's noise allows them.
- **Calibrating the panel.** `rreport eval calibrate` measures it (P27); a person labels the items and commits `calibrated = true` when it passes (runbook R5). Until then the gate ignores the panel's scores.
- **Real drafts.** The oracle writes no must-quote and no term; real models will. The joining of both is tested directly.
- **Annotation end to end through the real executables.** Articles run so since P22, the oracle answering on the wire ([testing.md](testing.md#end-to-end-killed-and-resumed)). An annotation does not yet: its two missions share one answer schema, which names both prompts, so the fake engine cannot tell them apart.
- **Candidates with CC BY.** None could be confirmed from here: YouTube shows the licence only on the watch page, which this environment cannot reach (`eval/sets/candidates.toml`).
